계획대로 **측정 → 판정 → 구현** 중 1·2단계다. 구현은 안 했다.

요청       80 (회사당 list.json + document.xml)

이번에는 문서 헤더대로 utf-8 로 읽었고 깨진 문자가 없다.

## 이름 길이 기준을 왜 4자로 했나

처음 센 값은 **89쌍**이었다. 눈으로 보니 셋이 섞여 있었다.

```
자기·계열   대한전선 → 대한전선 · (주)LS → LS ELECTRIC
이름 변형   한국전력 + 한국전력공사(주) 가 따로 세어짐 (Company/Stock 두 행)
짧은 이름   GS · NC · LS · KT 가 300자 창에서 아무 데나 걸린다
             롯데에너지머티리얼즈 → "NC, GS" 가 대표적인 소음
```

정규화(괄호·주식회사·공백 제거) + 자기 포함관계 제외 + 최소 길이로 다시 세면:

| 최소 길이 | 실명 지목 | 고유 쌍 |
| ---: | ---: | ---: |
| 2자 | 18 / 40 | 61 |
| 3자 | 16 / 40 | 39 |
| **4자** | **16 / 40** | **37** |
| 5자 | 14 / 40 | 25 |

4자에서 목록이 읽히기 시작하고 5자에서는 **기아·우진** 같은 진짜 거래처가
빠진다. 그래서 4자를 보고 값으로 쓰되, **이건 임계이지 해법이 아니다**(아래).

## 2단계 판정 — **구현할 값어치가 있다**

근거 넷:

1. **수율이 충분하다.** 40% · 37쌍. 182곳으로 넓히면 대략 73곳 · 170쌍이고,
   그러면 그래프에 **인과 술어가 처음 생긴다**(지금 accepted 0)
2. **배관이 이미 다 있다.** `SUPPLIES`·`CUSTOMER_OF` 정책 · 빌더 ·
   `analytics.firm_supply_relation` 테이블 전부 존재하고 데이터만 0행이다
3. **지어내기가 구조적으로 막혀 있다.** 빌더가
   `absenceSemantics: unknown_not_disclosed` 라 공시가 없으면 아무것도 안 만든다
4. **읽히는 것이 나온다.** 위 목록은 전부 사람이 확인 가능한 관계다

## 구현 전에 반드시 풀어야 할 것 — 이름 해소

**부분 문자열 매칭으로는 못 만든다.** 위 4자 임계는 측정을 읽으려고 쓴 것이지
빌더의 규칙이 될 수 없다. 남는 문제 셋:

- **계열사·모회사**: `(주)LS → LS일렉트릭` 은 거래처가 아니라 자회사다.
  `엘에스일렉트릭 → LS ELECTRIC` 은 같은 회사의 다른 표기다
- **지주사 보고서**: 포스코홀딩스의 목록은 포스코퓨처엠 것을 포함한 것으로
  보인다. 지주사 사업보고서는 자회사 사업을 함께 서술한다
- **짧은 이름**: `기아`(2자)는 진짜인데 `GS`(2자)는 소음이다. 길이로는 못 가른다

필요한 것은 **별칭 테이블 + 소유관계 제외 + 지주사 보고서의 섹션 귀속**이고,
이게 이 작업의 실제 비용이다. 수집은 이미 되는 것을 확인했다(80요청 · 오류 0).

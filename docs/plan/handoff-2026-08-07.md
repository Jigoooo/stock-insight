## 1. 지킬 작업 규율 (사용자 지시, 계속 유효)

- 관측으로 닫는다. "고쳤다" 가 아니라 **재측정한 수치**로 완료를 부른다
- 지어내지 않는다. 근거가 없으면 만들지 말고 **왜 안 만들었는지 기록**한다
- 못 한 것도 근거와 함께 보고한다. **조용히 범위를 줄이지 않는다**
- 커밋 메시지는 **한국어**로, 무엇을 **왜 하지 않았는지**까지
- 모든 응답은 한국어
- **자격증명 값은 절대 출력하지 않는다.** 이름만 보고하고 값은 셸 변수로 넘긴다

> 원래 "프로덕션 DB 쓰기와 배포는 실행 전 확인" 규칙이 있었으나 이 세션에서
> **"나한테 물어보지말고 계속 진행해"** 로 명시적으로 해제됐다. 새 세션에서는
> 기본값(확인받기)으로 돌아간다고 보는 게 안전하다.

### 치명적 함정 — 반드시 알고 시작할 것

1. **파이프라인 타이머가 워킹 트리를 실행한다.** 파일을 **편집하는 순간 배포**다.
   "커밋 전이라 안전하다" 는 여기서 거짓이다. 이 세션에서 마이그레이션 적용 전
   링커를 워킹 트리에 둬서 **파이프라인을 세 번 깨뜨렸다**
2. `pipeline_resolve_provenance` 가 시작·종료 시점에 git 추적 파일을 해시한다.
   실행 중 편집하면 `failed` 로 기록된다
3. `research_app` DB 는 **네 프로젝트 공유**다. 표를 건드리기 전
   `docs/operations/database-ownership.md` 를 열어라 — 그 문서에 함정 네 개가
   적혀 있고 이 세션은 **읽기 전에 그중 셋을 밟았다**
4. `source-contract-integrity.test.ts` 는 `STOCK_INSIGHT_SOURCE_REVISION_TEST_DB_URL`
   없으면 **조용히 skip** 한다. 마이그레이션 069 의 계약 위반이 하루 숨었던 이유

처음에 "용량 때문" 이라고 적었는데 **재보지 않고 쓴 변명**이었다. 재니 D·E 는

### C — 한국 거시 (ECOS) · 사용자가 다음 세션으로 미룸

준비 상태는 확인했다.


**스키마 변경 없이 수집기 하나면 된다.** `run-fred-vintage.ts` 가 그대로 본보기다.
`macro_series_topic` 도 함께 넣어야 한다 — A 에서 만든 parity 테스트가 안 그러면 잡는다.

### D — EXPOSES · **오진이었다. 크기가 다르다**

```
EXPOSES 원장 엣지    107
상태                 quarantined_unverified
막은 것              policy_status = 'provisional_review_required'
서술어 설명란        "semantic approval pending"
그 107개의 모양      Stock → Industry   ← 정책→기업이 아니다
```

**그리고 근본은 따로 있다 — 법안이 엔티티가 아니다.**

```
core.entity 아홉 종류
  Metric 329 · Company 325 · Stock 325 · LegalEntity 156 · Theme 138
  Industry 112 · Token 24 · ETF 18 · Exchange 3
  ← 법안도 일정도 없다
```

495개 법안 액션은 `market.scheduled_event` 라는 **평범한 표**에 있지 그래프 노드가
아니다. **`EXPOSES` 를 승인해도 이을 쪽 끝이 없다.**

> **D 는 "잡 하나 쓰기" 가 아니라 "법안을 엔티티로 볼 것인가" 라는 설계 결정이다.**
> 사용자 확인이 필요한 종류의 일이다.

**그리고 이건 EXPOSES 만의 문제가 아니다 — 이 세션 최대 미청구 발견:**

```
격리된 엣지  3,312   서술어 16종
  COMMON_OWNER 1,062 · AFFECTS 616 · PEER_OF 174 · ROLLS_UP 129 · EXPOSES 107 ...
```

계산이 끝나 원장에 들어와 있는데 **온톨로지 승인 한 줄**에 막혀 서빙까지 못 간다.
"만들어 놓고 안 쓴다" 의 **가장 큰 사례**인데 이 세션은 마지막에야 셌다.

### E — 유니버스·ETF · **등급을 잘못 매겼다 (3등급 → 2등급)**

계획이 "남의 저장소" 로 분류했는데 **`public.entities` 를 보고 거기서 멈춘 것**이었다.

```
core.v_security_universe = core.entity + core.listing + core.entity_identifier
                           ← 전부 우리 스키마. public.entities 를 안 읽는다
run-core-identity-sync.ts  ← 우리 잡. core.entity 에 쓴다
  :27  FROM public.entities legacy   ← 남의 것은 이 *읽기* 하나뿐
KRX_API_KEY                .env 에 있음. 읽는 코드 0개
```

**KRX 피드를 그 잡의 두 번째 원천으로 붙이면 교차 저장소 쓰기가 아니다.**

다만 **넓히는 게 목적이 되면 안 된다.** 이 세션이 잰 것:

```
미귀속 사건 2,641 중 유니버스 회사를 언급한 것   163 (6.2%)
```

나머지 93.8% 가 미귀속인 것은 **필터가 맞게 도는 것**이지 결함이 아니었다.
KOSPI/KOSDAQ 전체는 194 → 2,500+, **13배**고 비용도 13배다.
**"무엇을 보고 싶은가" 를 먼저 정해야 한다.**

### 1. 시장 전반 뉴스 화면 — 완료 (2026-08-03)

`/workspace/market-topic-news`. 계약 → 읽기 모델 → 엔드포인트 → 패널까지 붙었고,
매칭된 용어를 각 줄에 노출한다. 용어별 건수 표도 함께 낸다(0건 용어 포함).

리더 역할(`stock_insight_app_reader`) + `BEGIN READ ONLY` 로 실제 코드 경로를 태워
얻은 값이다:

```
쓰이는 용어             35      걸린 것 없는 용어 10개
미귀속 관측            901
  어휘에 걸린 것         86      ← 83 아님. 아래 참조
표시한 줄               79      중복합 86 = 매칭 86 으로 정확히 맞음
  원문 링크 있는 것      79 / 79
  출처 이름 있는 것      79 / 79
```

**83 이 86 이 된 이유.** 이 문서 위쪽과 마이그레이션 063 주석의 83 은 대소문자를
구분한 매칭이었다. 읽기 모델은 대소문자를 무시한다. 늘어난 3건은 전부
`Treasury`(대문자)가 시드된 `treasury`(소문자)에 걸린 것이고 — 사건 6675·6866·6968,
30년물 국채 금리와 미 재무부의 엔화 개입 — 셋 다 진짜 시장 뉴스다. 반대로 대소문자
구분 매칭만 잡아내던 항목은 없었다. 3건 얻고 0건 잃는 교환이라 바꿨다.
**코퍼스가 변한 게 아니라 매칭 규칙이 바뀐 것이다.**

`market-news` 라는 이름의 모듈이 이미 있지만 **다른 화면**이다. 그쪽은 레거시
`public.v_user_feed_dedup` / `public.source_documents` 를 읽는다. 새 것은
`market-topic-news` 로 이름을 갈라 두었으니 합치지 말 것.

### 2. 배포

마지막 배포는 `4ca2e94`. 그 뒤 커밋들(리비전 정체성, 텍스트 귀속, 시장 어휘,
소유권 문서, 시장 전반 뉴스 화면)이 배포 전이다. 웹 빌드는 이제 2분이다.

시장 전반 뉴스는 마이그레이션을 추가하지 않는다. 읽기만 하고, 읽는 테이블
(`analytics.market_topic_term`·`serving.v_knowledge_event_current_v1`·
`knowledge.document`·`ingestion.source`)은 리더 역할이 이미 `SELECT` 권한을 갖고
있다 — 스키마 기본 권한(`pg_default_acl`)이 잡아 준다. `has_table_privilege` 로
확인했다. 즉 `repin-live-database-digests.mjs` 가 막을 종류의 권한 변경은 없다.

배포 전 반드시:
```bash
bash ops/scripts/verify-production-compose.sh
DATABASE_URL=… node ops/scripts/repin-live-database-digests.mjs
bash ops/scripts/verify-table-ownership.sh
bash ops/scripts/verify-systemd-units.sh
```
두 번째가 중요하다. 마이그레이션이 리더 역할의 권한을 바꾸면 브레인이
크래시루프에 빠진다. 2026-08-03 에 그렇게 45분 내려갔다.

## 고친 기존 결함 — 스테일 테스트

`workspace-relation-crossfade.test.ts` 가 이 세션 이전부터 깨져 있었다. `pnpm test`
가 `verify:release` 사슬 중간에 있어 **배포 게이트가 build 까지 가지도 못했다.**

원인은 CSS 가 아니라 테스트였다. `1edcf81`("워크스페이스 제품 UI 수렴")이 표
스타일을 페이지 CSS 에서 공용 `Table` 로 옮겼는데, 규칙은 온전히 살아 있고
테스트의 참조 경로만 옛 위치에 남았다. 정규식이 빈 문자열을 잡았고, 빈 문자열은
`doesNotMatch` 짝을 조용히 통과시켰다.

- 규칙은 `shared/ui/table/table.module.css` 의 `.row:hover` 에 있다.
  `background` 만 쓰고 `transform`/`translate`/`scale` 은 없다 — 테스트가 지키려던
  조건 그대로다.
- 테스트가 그 파일을 보게 고쳤다. `.tableWrap` 을 페이지 CSS 에 되살리는 쪽은
  택하지 않았다. 그러면 리팩터가 일부러 없앤 중복 스타일이 되살아난다.
- 빈 문자열이 통과하던 구멍도 막았다. 규칙이 있다는 것을 먼저 단언한 뒤 내용을 본다.

**한 번 틀렸던 판단을 남긴다.** 처음에는 `status-view.tsx` 의 `styles.tableWrap` 이
`undefined` 인 것을 보고 "커버리지 표에 가로 스크롤 컨테이너가 없다"고 적었다.
틀렸다. 실제 스크롤 컨테이너는 공용 `Table` 이 만든다
(`shared/ui/table/table.module.css` 의 `.container { overflow-x: auto }`).
`styles.tableWrap` 은 아무 효과 없는 바깥 div 일 뿐이고, 스크롤 결함은 없다.
**클래스 이름이 없다는 사실에서 동작이 없다고 추론한 오류다** — 위쪽 오류 목록 2번,
"단어 매칭은 소유 증거가 아니다" 와 같은 모양이다.

새 화면은 `.statusTable` 을 재사용하지 않고 자기 CSS 모듈을 쓴다. 그 클래스의
모바일 라벨이 상태 페이지 열 이름(`데이터 영역`·`상태`·`항목 수`·`최근 확인`)으로
하드코딩돼 있어, 3열짜리 어휘 표에 재사용하면 모바일에서 틀린 라벨이 붙는다.

## 조사할 때 반복해서 틀린 것 — 같은 순서로 틀리지 않도록

이 세션에서 실제로 낸 오류들이다.

1. **`pg_stat_user_tables.n_live_tup` 은 추정치다.** `analytics.theme` 이 138행인데 0으로 나온다. 소유권·존재 판단에는 `count(*)` 를 써야 한다
2. **단어 매칭은 소유 증거가 아니다.** `theme` 으로 grep 하면 다른 프로젝트의 SQLite 테이블과 `'theme:crypto'` 문자열 라벨이 걸린다. 스키마 한정 참조나 실제 INSERT 를 봐야 한다
3. **`search_path` 를 쓰는 프로젝트는 스키마 한정 grep 에 안 잡힌다.** research-common 이 그렇다
4. **마이그레이션만 참조하는 테이블은 런타임 grep 에서 0 으로 보인다.** 둘을 나눠 세야 한다
5. **`public.entities` 와 `core.entity` 는 다른 id 공간이다.** 잘못 조인하면 `EV/2차전지 → THEME:cybersecurity` 같은 헛것이 나온다
6. **테이블이 있다고 그 테이블이 하려던 일이 가능한 것은 아니다.** 커버리지 원장은 기록만으로 채워졌고, exposure 원장과 테마 다리는 아니었다. 다리를 놓기 전에 건널 것이 있는지 확인할 것
7. **할당량·레이트 리밋을 기억에서 쓰지 말 것.** OpenDART 일일 한도를 20,000 으로 적었다가 361 요청에서 소진됐다. 잡 자신의 `quotaExhausted` 기록이 유일한 증거다

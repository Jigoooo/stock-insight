# C — ECOS 수집기 (2026-08-07)

인수인계 §4 C 는 ECOS 를 **"스키마 변경 없이 수집기 하나면 된다"** 로 적었다.
수집은 그 말이 맞았다. **그래프 연결은 아니었다** — 재보니 막힘이 셋 있다.

---

## 1. 만든 것 — `run-ecos-vintage.ts`

`run-fred-vintage.ts` 를 본으로 삼되 **한 가지 구조적 차이**가 있고, 숨기지 않고 코드
머리말에 적었다.

**ECOS 에는 빈티지 축이 없다.** FRED/ALFRED 는 `realtime_start`/`realtime_end` 를
노출해 "그 날짜에 무엇을 알고 있었는가" 를 그대로 준다. ECOS `StatisticSearch` 는
관측의 **현재 값만** 준다 — 개정되면 옛 값은 조회할 방법이 없다.

그래서:

```
vintage_quality   'approx_collected'   ← macro_vintage CHECK 이 허용하는 다른 값
vintage_date      = observation_date   ← 수집일이 아니라 관측일
```

`vintage_date` 를 수집일로 두면 기본키 `(series_key, observation_date, vintage_date)`
때문에 **매일 밤 전체 이력이 통째로 재삽입된다.** 삽입 수는 건강해 보이고 내용은 순수
중복이다 — 이 저장소가 반복해서 밟은 그 모양이다. 관측일로 두면 멱등하고, 위 다섯 계열은
당일 공표·무개정이라 근사가 실제로 참이다. **개정되는 계열을 여기 추가하려면 이 판단을
다시 해야 한다.**

## 2. 계열 선정 — 후보 공간이 일곱뿐이다

나머지는 월간 이하이고, 상관 모델은 월간을 이미 측정해서 버린다(재표본 57~59관측 <
최소 60, `MACRO_SERIES_EXCLUSIONS`). **그 일곱이 후보 공간 전부다.**

  바뀔 때만 움직이는 행정금리다. 시장 가격이 아니다.

## 3. 드라이런 — 삽입 수가 아니라 모양을 봤다

```
총 관측 15,661 (2015-01-01~)
```

| 계열 | n | 범위 | 연평균 | 주말 행 | 값 범위 |
| --- | ---: | --- | ---: | ---: | --- |
| 국고채(3년) | 2,857 | 2015-01-02~2026-08-06 | 246.3 | **0** | 0.795~4.548 |
| 국고채(10년) | 2,857 | 〃 | 246.3 | **0** | 1.172~4.632 |
| 회사채(3년,AA-) | 2,857 | 〃 | 246.3 | **0** | 1.626~5.736 |
| CD(91일) | 2,857 | 〃 | 246.3 | **0** | 0.630~4.030 |
| 기준금리 | 4,233 | 2015-01-01~2026-08-04 | **365.0** | **1,209** | 0.500~3.500 |

읽히는 것들이다. 시장금리 4종은 주말 행이 0이고 연 246일 — 한국 거래일 수다.
기준금리만 연 365일에 주말 행 1,209 — **달력일 계단함수**이고, 값 0.50~3.50% 는 실제
BOK 정책금리 이력(코로나 0.5%, 고점 3.5%)과 맞는다. 회사채가 국고채보다 항상 위인 것도 맞다.

> 기준금리는 **상관 쌍을 못 만들 것으로 예상하고** 넣었다. 계단함수라 일간 변화가 거의
> 전부 0이다. 넣은 이유는 한국 `rates` 주제의 앵커이고 `market.scheduled_event` 가 이미
> 2026-08-28 금통위를 들고 있어서다. **쌍이 0이면 그것이 예상된 결과이지 실패가 아니다.**

## 4. 그래프 연결은 "막힘 없음" 이 아니었다 — 막힘 셋

인수인계는 *"`macro_series_topic` 도 함께 넣어야 한다 — parity 테스트가 안 그러면 잡는다"*
로 적었다. **둘 다 틀렸다.**

### 막힘 1 — 상관 경로가 `FRED_SERIES` 에 하드와이어돼 있다

`run-v2-graph-publish.ts` 의 `MACRO_SERIES_WINDOW_SQL`:

```sql
JOIN core.entity_identifier identifier
  ON identifier.identifier_type = 'FRED_SERIES'
```

**한국 계열은 매핑을 무엇으로 주든 상관 모델에 들어갈 수 없다.** `ECOS_SERIES` 는
`identifier_type` CHECK 에 있지만(008:32) 실제 행은 **0개**이고 이 조인이 읽지도 않는다.

### 막힘 2 — 로드 대상은 `MACRO_SERIES_TRANSFORMS` 가 정한다

```ts
const includedSeries = Object.keys(MACRO_SERIES_TRANSFORMS).sort();
```

여기 없는 계열은 **애초에 조회되지 않는다.** 크래시가 아니라 조용한 무동작이다.

### 막힘 3 — 그 표를 건드리면 모델 설정 해시가 바뀐다

`MACRO_SERIES_TRANSFORMS` 는 `MACRO_COMOVEMENT_MODEL_CONFIG` 에 들어가고, 그 설정은
`model_config` 증거로 기록된다. 항목을 추가하면 **기존 MACRO_COMOVEMENT 엣지 전부가
다음 발행에서 새 리비전을 받는다.** 되돌릴 수 없는 사고는 아니지만(원장은 append-only)
의도해서 해야 하는 변경이다.

### 그래서 패리티 테스트를 확장했다

`macro-series-list-parity.test.ts` 가 `fred:` 만 훑고 있었다. ECOS 까지 보게 고쳤고,
계열 키를 **접두어까지 통째로** 비교하게 바꿨다(옛 버전은 접두어를 떼고 비교해서
ECOS 항목코드와 FRED 계열 id 가 조용히 매칭될 수 있었다).

다섯 계열은 `COLLECTED_WITHOUT_TOPIC` 에 **이유와 함께** 올렸다. 매핑이 생기면 테스트가
실패하므로, 이 미완성은 **테스트된 사실**이지 잊힌 구멍이 아니다.

## 5. 부수 발견 둘 — 둘 다 이번 작업 밖이라 기록만

### `fred:DHHNGSP` 는 680 빈티지를 모으고 그래프에 닿는 곳이 0이다

어제(2026-08-06) A 가 *"에너지 주제가 한 계열에 얹히지 않게"* 넣은 계열이다. 실측:

```
market.macro_vintage 행                680
MACRO_SERIES_TRANSFORMS / FREQUENCY    없음
MACRO_SERIES_EXCLUSIONS                없음 (이유도 안 적혀 있다)
그래프 관계 (모든 서술어)                 0
```

크래시는 안 난다 — 막힘 2 때문에 조용히 빠진다. 분석 파이프라인은 이 계열이 추가된
2026-08-06 16:28 **이후 아직 안 돌았다**(마지막 실행 08-06 07:47, 다음 08-07 07:46).
다음 실행에서 `MEASURED_BY` 엣지는 생기지만 **주식까지 가는 다리는 여전히 없다.**
A 의 목적은 절반만 달성된 상태다.

### ECOS 가 KOSPI 를 1995년부터 일별로 준다 — `MARKET_FACTOR_SQL` 의 전제가 깨졌다

`run-v2-graph-publish.ts:409` 의 주석:

> *"KR has no usable index: ^KS11 exists only in `stock.market_snapshots` and only for
> 141 days (2026-04-30 onward), far short of the correlation window."*

그래서 한국 시장 팩터를 **우리 보유 종목의 동일가중 합성지수**로 만들고 있다.
`802Y001 / 0001000 KOSPI지수` 는 **1995-01-03부터 일별**이다. 전제가 사실이 아니다.

**그럼에도 이번에 넣지 않았다.** 시장 팩터를 바꾸면 **모든 한국 엣지의 베타 통제**가
바뀐다. 계열 목록 한 줄이 아니라 전후 측정이 딸린 모델링 결정이다. 잃어버리지 않도록
여기 청구해 둔다.

## 6. 하지 않은 것과 이유

| 안 한 것 | 이유 |
| --- | --- |
| `--apply` 수집 실행 | **프로덕션 DB 쓰기.** 실행 전 사용자 확인이 필요하다 |
| `macro_series_topic` 마이그레이션 | 막힘 1 이 안 풀리면 갈 곳 없는 Metric 엔티티와 MEASURED_BY 엣지를 만든다 — DHHNGSP 가 지금 그 상태다 |
| `MACRO_SERIES_WINDOW_SQL` 조인 확장 | 라이브 분석 경로 변경. 막힘 3 과 묶어서 판단해야 한다 |
| `MACRO_SERIES_TRANSFORMS`/`FREQUENCY` 항목 추가 | 막힘 3 — 기존 거시 엣지 전부가 새 리비전을 받는다 |
| 파이프라인 스크립트 배선 | 위가 정해지기 전에는 워킹 트리에 배선을 두지 않는다 (§2-1 함정) |
| `fred:DHHNGSP` 수정 | 어제 작업의 미완성분이다. 같은 결정(막힘 3)에 걸려 있어 함께 판단하는 게 맞다 |
| KOSPI 시장 팩터 교체 | 모델링 결정. §5 |

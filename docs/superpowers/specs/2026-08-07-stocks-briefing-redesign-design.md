# 내 종목 브리핑 개편 설계

## 목표

`내 종목` 탭을 가격과 분석 상태를 나열하는 표에서, 오늘 보유종목에 생긴 변화를 우선순위대로 확인하는 개인화 리서치 화면으로 바꾼다.

증권사 앱처럼 평가금액과 누적 수익률을 관리하는 화면이 아니라 다음 질문에 답하는 것이 목적이다.

- 오늘 어떤 보유종목을 먼저 확인해야 하는가?
- 어떤 시장 변화와 뉴스가 그 종목에 연결되는가?
- 추가로 확인할 리스크와 다음 점검 지점은 무엇인가?
- 기존 보유 논지와 현재 변화가 어떻게 이어지는가?

백엔드, DB, 스키마와 실제 API 계약은 이번 개발 전용 화면 단계에서 변경하지 않는다. 데이터가 없는 브리핑 필드는 개발 fixture로 제공하고, 실제 화면 연결 시 여러 종목의 브리핑을 한 번에 제공하는 배치 응답을 별도 설계한다.

## 확인된 현재 문제

현재 화면은 7열 종목 표와 우측의 12개 분석 축 아코디언으로 구성된다.

- 사용자가 먼저 알아야 할 변화보다 종목 속성과 분석 상태가 앞선다.
- 데이터가 없는 분석 축도 아코디언 제목으로 노출되어 나열감이 강하다.
- 보유종목과 관심종목의 역할 차이가 약하다.
- 뉴스, 영향 경로, 리스크가 한 흐름으로 이어지지 않는다.
- 종목 표의 가격·등락 정보가 증권사 앱과 유사하지만 Stock Insight만의 리서치 목적은 드러나지 않는다.

## 선택한 방향

### 채택: 우선순위 브리핑과 종목 현황의 결합

화면 상단에는 오늘 확인할 보유종목을 최대 3개까지 보여주고, 옆 또는 아래에는 전체 보유종목 상태를 제공한다. 관심종목은 별도 구역에서 변화가 생긴 항목만 우선 노출한다.

이 방향을 채택한 이유는 다음과 같다.

- `오늘` 탭에서 발견한 변화를 `내 종목`에서 구체적으로 점검하는 흐름이 자연스럽다.
- 가격 조회보다 변화의 이유와 확인할 위험을 앞세워 제품 정체성이 분명하다.
- 모든 종목을 같은 크기의 카드로 반복하거나 한 종목 상세가 첫 화면 대부분을 차지하는 문제를 피한다.
- 데스크톱과 모바일에서 같은 정보 순서를 유지할 수 있다.

### 제외한 방향

- 모든 보유종목을 같은 크기의 카드로 나열하는 방식: 중요도 차이가 사라지고 반복 정보가 많아진다.
- 좌측 목록과 우측 고정 상세만 사용하는 방식: 현재 화면과 차이가 작고 첫 진입 시 우선 확인할 변화가 드러나지 않는다.
- 평가금액·누적 수익률 중심 포트폴리오 대시보드: 증권사 앱과 중복되고 현재 종목 응답에 필요한 비용 기준 데이터가 포함되어 있지 않다.

## 화면 정보 구조

### 1. 내 종목 브리핑 헤더

상단 요약은 다음 네 값만 제공한다.

- 보유종목 수
- 새로 연결된 뉴스 수
- 확인할 리스크 수
- 마지막 분석 시각

평가금액, 누적 수익률, 매입단가는 표시하지 않는다. 현재가와 당일 등락은 종목 행의 보조 정보로만 사용한다.

### 2. 오늘 우선 확인할 종목

보유종목 중 최대 3개를 표시한다. 같은 종목에 여러 뉴스가 연결되어도 한 개의 통합 브리핑으로 묶는다.

각 브리핑은 다음 정보를 가진다.

- 우선순위와 종목명
- 오늘의 핵심 변화 한 문장
- 내 종목에 연결된 이유
- 연결 뉴스 개수
- 대표 시장 연결 경로
- 확인할 리스크
- 현재가와 당일 등락

원시 점수나 매수·매도 판단은 노출하지 않는다. 우선순위는 fixture가 명시적으로 제공하며, 실제 연동 단계에서는 서버가 계산한 표시 순서를 사용한다.

### 3. 전체 보유종목

모든 보유종목을 간결한 목록으로 제공한다.

- 종목명과 시장
- 현재 상태
- 현재가와 당일 등락
- 새 변화, 새 뉴스, 확인할 리스크 유무
- 마지막 분석 시각

변화가 없는 종목도 이 구역에서는 확인할 수 있다. 상단 우선 브리핑과 같은 종목을 선택해도 동일한 상세를 연다.

### 4. 관심종목에서 생긴 변화

보유하지 않았지만 관심종목으로 등록한 항목 중 새 변화가 있는 종목만 우선 표시한다.

- 최근 이슈
- 관심종목으로 표시된 이유 또는 기본 논지
- 확인할 리스크
- 현재가와 당일 등락

변화가 없는 관심종목은 반복 카드로 나열하지 않고 `전체 관심종목 보기`에서 확인한다.

## 상세 상호작용

### 기본 표시

상단 브리핑, 전체 보유종목, 관심종목 축약 카드는 모두 같은 선택 상태를 사용한다. 선택하면 우측 드로어로 상세를 연다.

- 오늘 탭과 동일한 포털 기반 고정 드로어를 사용한다.
- 기존 페이지 레이아웃과 스크롤 위치를 바꾸지 않는다.
- 밝은 차단 오버레이를 사용한다.
- 오버레이 클릭은 상세만 닫고 뒤의 종목을 활성화하지 않는다.
- 드로어 너비 조절과 세션 기억을 지원한다.
- `넓게 보기`로 중앙 모달 전환이 가능하다.
- 새 종목을 선택해 열면 기본 표시 방식은 다시 드로어다.
- 모바일에서는 기존 하단 모달을 사용한다.

### 드로어 상세 순서

기존 12개 분석 축 아코디언을 그대로 노출하지 않는다. 실제 데이터가 있는 구역만 다음 순서로 보여준다.

1. 종목 요약
   - 종목명, 시장, 보유·관심 상태
   - 현재가, 당일 등락, 분석 기준 시각
2. 왜 지금 확인해야 하나
   - 오늘 가장 중요한 변화
   - 내 종목에 연결된 이유
   - 연결 뉴스 수와 근거 수준
3. 시장 연결 경로
   - 대표 경로 1~3개
4. 관련 뉴스
   - 중요도순 최대 3건
   - 제목, 요약, 출처, 발행 시각, 원문 링크
5. 확인할 리스크
   - 반대 근거와 다음 확인 지점
6. 보유 논지 복기
   - 기존 기본 논지
   - 현재 변화와 함께 확인할 항목

보유 논지 복기는 정보 제공과 회고만 수행하며 목표가, 손절가, 매수·매도 지시를 포함하지 않는다.

### 넓은 모달

모달 전환은 상세 데이터를 다시 요청하지 않는다. 같은 데이터를 넓은 2열 구성으로 재배치하고 다음 정보를 추가로 펼친다.

- 관계 그래프
- 제공 가능한 기업 프로필과 재무·실적 지표
- 드로어에서 축약한 연결 경로와 관련 뉴스 전체

관계 그래프와 기업 지표가 없으면 해당 구역을 만들지 않는다.

## 데이터 경계

### 이번 개발 전용 화면

- 현재 `StockListResponse`의 보유·관심 상태, 현재가, 당일 등락, 기본 논지, 분석 상태를 재사용한다.
- 상세 선택 시 기존 종목 상세, 관계, 영향 브리프 로더를 사용한다.
- 상단 요약, 종목별 핵심 변화, 연결 뉴스 수, 대표 경로와 리스크 요약은 개발 fixture가 제공한다.
- 카드마다 상세 데이터를 사전 요청하지 않는다.
- 제품 DB, 마이그레이션과 공개 API 계약은 변경하지 않는다.

### 실제 화면 연결 단계

실제 데이터 연결은 한 번의 종목 화면 응답으로 브리핑 목록을 받을 수 있는 배치 read model을 사용한다. 종목별 상세 API를 반복 호출하는 N+1 구조는 허용하지 않는다.

배치 응답은 최소한 다음 정보를 제공해야 한다.

- 네 개의 상단 요약 값
- 표시 순서가 확정된 우선 보유종목 브리핑 최대 3개
- 전체 보유종목의 변화·뉴스·리스크 유무
- 변화가 있는 관심종목 브리핑
- 각 항목의 데이터 기준 시각과 근거 수준

DB 스키마 변경 필요 여부는 실제 read model 설계 단계에서 현재 뷰와 파이프라인 데이터를 확인한 뒤 결정한다. 이번 목업 구현에 선행하지 않는다.

## 데이터 부족과 실패 처리

- 연결 뉴스가 없으면 `새로 연결된 뉴스 없음`으로 표시한다.
- 대표 영향 경로가 없으면 연결 경로 구역을 숨긴다.
- 리스크가 없으면 `확인할 리스크가 아직 정리되지 않았습니다`로 표시한다.
- 보유 논지가 없으면 작성된 문장처럼 생성하지 않고 빈 상태를 표시한다.
- 가격 기준 시각이 오래됐으면 값보다 데이터 기준 시각을 강조한다.
- 상세 로딩 실패는 선택 상태를 유지하고 드로어 안에서 다시 불러오기를 제공한다.
- 관계 또는 영향 데이터만 실패하면 종목 기본 상세와 뉴스는 유지하고 실패한 구역만 부분 상태로 표시한다.
- 전체 보유종목이 없으면 관심종목 구역을 첫 콘텐츠로 올리고 보유종목 등록 방법을 안내한다.
- 관심종목도 없으면 종목 검색과 관심종목 등록으로 이어지는 단일 빈 상태를 제공한다.

## 반응형과 시각 규칙

- 데스크톱은 우선 브리핑과 전체 보유종목을 2열로 배치한다.
- 1240px 이하에서는 우선 브리핑, 전체 보유종목, 관심종목 순으로 세로 배치한다.
- 모바일에서도 정보 순서와 중요도는 바꾸지 않는다.
- 선택된 상단 브리핑, 보유종목 행, 관심종목 카드는 동일한 배경·전체 보더·그림자를 사용한다.
- 카드와 목록 사이에는 선택 보더와 그림자가 잘리지 않을 안쪽 여백을 둔다.
- 종목명, 뉴스 제목, 연결 경로와 리스크 문장은 카드 밖으로 넘치지 않게 줄바꿈한다.
- 색만으로 상승·하락, 선택, 데이터 부족 상태를 구분하지 않는다.
- 모든 모션은 기존 CSS와 로컬 motion 경계만 사용하고 `prefers-reduced-motion`을 지원한다.

## 컴포넌트 경계

- 페이지용 브리핑 모델은 개발 fixture와 향후 배치 응답이 같은 형태로 제공할 수 있게 종목 화면 모델 계층에 둔다.
- `StocksView`는 화면 순서, 선택 상태와 상세 열기만 소유한다.
- 우선 브리핑 목록, 전체 보유종목 목록과 관심종목 변화 목록은 각각 한 역할의 하위 컴포넌트로 분리한다.
- 종목 상세 표시 방식은 오늘 탭의 근거 인스펙터와 같은 Dialog 프리미티브와 너비 모델을 재사용한다.
- 상세 내용 컴포넌트는 드로어와 모달에서 공유하고 배치만 프레젠테이션 속성으로 바꾼다.
- 실제 데이터 수집과 우선순위 계산을 브라우저 UI에 구현하지 않는다.

## 검증 기준

- 첫 화면에서 오늘 우선 확인할 보유종목 최대 3개가 전체 목록보다 먼저 보인다.
- 같은 종목의 여러 뉴스가 하나의 브리핑으로 합쳐지고 연결 건수가 별도로 표시된다.
- 평가금액, 누적 수익률과 매수·매도 지시 문구가 없다.
- 상단 브리핑, 전체 보유종목과 관심종목 카드가 같은 상세를 연다.
- 드로어가 페이지 기하를 바꾸지 않고 오버레이 클릭은 뒤 항목을 활성화하지 않는다.
- 드로어 너비 조절, 모달 전환, 바깥 클릭, Escape와 포커스 복귀가 오늘 탭 계약과 일치한다.
- 상세 원문 링크가 실제 URL을 새 탭으로 연다.
- 부분 데이터, 전체 빈 상태, 상세 실패와 재시도 상태가 구분된다.
- 데스크톱, 1240px 이하, 390px 모바일에서 내용 잘림과 불필요한 가로 스크롤이 없다.
- 라이트·다크 모드, 키보드, 접근성 smoke, reduced-motion을 검증한다.
- 포맷, lint, typecheck, 테스트와 build를 통과한다.

## 제외 범위

- 증권사 계좌 연동
- 주문, 매수·매도와 목표가 기능
- 평가금액·누적 수익률 대시보드
- 이번 단계의 DB 마이그레이션 또는 실제 브리핑 API 추가
- 실제 데이터 우선순위 모델의 가중치 설계
- 관심종목 관리 기능의 재설계
- 다른 탭의 정보 구조 변경

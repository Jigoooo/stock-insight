# 시장 연결 탭 개편 설계

## 목표

`시장 연결` 탭을 여섯 가지 시각화 모드를 나열하는 기술 화면에서, 다음 질문에 답하는 개인화 시장 리서치 화면으로 바꾼다.

> 오늘 시장에서 어떤 변화가 생겼고, 그 변화가 내 보유·관심 종목에 어떻게 이어지며, 무엇을 더 확인해야 하는가?

사용자는 시장 변화를 먼저 읽고, 연결된 종목과 영향 경로를 따라가며, 근거와 반대 가능성을 확인한다. 화면은 계속 읽기 전용이며 주문, 매매 실행, 목표가, 매수·매도 지시를 제공하지 않는다.

이번 단계에서는 DB, 마이그레이션, 수집 작업과 공개 API 계약을 변경하지 않는다. 백엔드 데이터 보강이 진행 중이므로 개발 프리뷰 fixture로 완성된 경험을 검증하고, 실제 화면은 현재 Radar·지도 응답에서 증명되는 정보만 표시한다.

## 확인된 현재 문제

현재 `RadarView`는 `MarketOverviewPanel` 안에서 다음 여섯 화면을 동등한 모드로 제공한다.

- 이벤트 레이더
- 요인 지도
- 전파 지도
- 히트맵 행렬
- 타임라인
- 세계 지도

이 구성에는 다음 문제가 있다.

- 사용자가 무엇부터 확인해야 하는지보다 시각화 종류 선택이 먼저 나온다.
- 신호 한 건의 강도·종목·요약은 보이지만 여러 종목에 연결된 하나의 시장 변화로 읽히지 않는다.
- `강도 82` 같은 원시 숫자의 의미가 설명되지 않아 확률이나 가격 전망처럼 오인될 수 있다.
- 보유·관심 종목 연결과 시장 전반 변화가 한 목록에서 같은 밀도로 반복된다.
- 지도·팩터·전파·히트맵·타임라인의 역할 차이를 일반 사용자가 스스로 해석해야 한다.
- 행을 선택해도 변화의 근거, 영향 경로, 연결 종목과 리스크를 한 흐름으로 확인하는 상세 경험이 없다.

## 선택한 방향

### 채택: 시장 변화 이야기 우선

첫 화면은 시장 변화를 이야기 단위로 보여주고, 각 변화에서 연결된 보유·관심 종목과 리스크로 내려간다.

정보 흐름은 다음 순서로 고정한다.

1. 시장 변화
2. 연결된 내 보유·관심 종목
3. 영향 경로
4. 근거와 관련 원문
5. 반대 근거와 확인할 리스크

이 방향을 채택한 이유는 다음과 같다.

- `오늘` 탭에서 발견한 사건을 시장 맥락 안에서 더 깊게 탐색하는 흐름이 자연스럽다.
- `내 종목` 탭의 종목 중심 브리핑과 역할이 겹치지 않는다.
- 지도와 관계 그래프를 제품의 시작점이 아니라 이해를 돕는 보조 도구로 사용할 수 있다.
- 개인화 데이터가 적은 사용자에게도 시장 전반 변화로 유용한 화면을 제공할 수 있다.

### 제외한 방향

- 내 종목 영향도부터 정렬하는 방식: 개인화는 강하지만 `내 종목` 탭과 역할이 겹친다.
- 영향 경로·지도부터 시작하는 방식: 분석 도구의 성격은 강하지만 일반 사용자의 첫 진입 학습 비용이 크다.
- 모든 변화를 같은 크기의 카드로 나열하는 방식: 우선순위 차이가 사라지고 기존의 나열감이 반복된다.
- 대표 변화 하나가 화면 대부분을 차지하는 방식: 집중력은 높지만 다른 연결을 비교하기 어렵다.

## 화면 정보 구조

### 1. 시장 연결 헤더

상단은 다음 네 값을 제공한다.

- 오늘 감지한 주요 시장 변화 수
- 내 보유·관심 종목에 직접 연결된 변화 수
- 확인할 리스크 수
- 분석 기준 시각

실제 Radar 응답은 페이지 전체의 직접 연결 수와 리스크 수를 제공하지 않는다. 두 값은 `—`와 `집계 데이터 없음`으로 표시한다. 현재 불러온 페이지의 항목 수를 전체 집계처럼 사용하지 않으며, 원시 강도의 평균이나 합산 점수도 상단 요약에 사용하지 않는다.

### 2. 내 종목에 연결된 주요 변화

보유·관심 종목과 연결된 변화 중 최대 3개를 카드로 표시한다. fixture는 명시된 순서를 사용하고, 실제 화면은 현재 Radar 응답의 서버 순서를 보존한다. 브라우저에서 새로운 우선순위 점수를 계산하지 않는다.

각 카드는 다음 정보를 가진다.

- 우선순위와 시장·지역
- 핵심 변화 한 문장
- 왜 지금 확인해야 하는지
- 연결된 보유·관심 종목
- 대표 영향 경로
- 확인할 리스크 요약
- 발생 시각과 데이터 기준 시각
- 강도 표현 `강함`, `보통`, `낮음`

목록에서는 원시 0–100 강도 값을 노출하지 않는다. 카드 선택 시 상세에서 원시 값과 산정 의미를 함께 설명한다.

### 3. 그 밖의 시장 변화

우선 카드에 포함되지 않은 변화는 카드가 아닌 밀도 높은 선택 행 목록으로 제공한다.

표시 순서는 다음과 같다.

1. 보유종목 직접 연결
2. 관심종목 직접 연결
3. 간접 연결
4. 내 종목 연결이 없는 시장 전반 변화

실제 화면은 현재 Radar 응답이 이미 제공하는 순서를 유지한다. UI는 `holding`, `watched` 플래그로 구역을 나누되 같은 구역 안의 순서를 재계산하지 않는다.

각 행은 시장·지역, 변화 제목, 연결 범위, 발생 시각과 강도 라벨을 보여준다. 내 종목 연결이 없으면 빈 개인화 문장을 만들지 않고 `시장 전반 변화`로 표시한다.

기존 커서 기반 `더 보기`는 이 목록에 유지한다. 추가 페이지를 불러와도 이미 표시한 항목은 중복하지 않고, 새 행이 추가됐음을 키보드와 스크린리더에 알린다.

### 4. 시장 흐름 더 살펴보기

현재 여섯 모드를 첫 화면의 동등한 탭으로 유지하지 않는다. 주요 변화와 전체 목록 아래의 보조 탐색 구역으로 이동한다.

- `세계 지도`: 시장 변화의 지리적 위치와 데이터 정밀도 확인
- `요인별 변화`: 신호 유형별 관측 수, 강도 범위와 대상 비교
- `전파 경로`: 시장 요인이 기업·업종으로 이어지는 방향 확인
- `시간 흐름`: 같은 유형의 변화가 언제 발생했는지 확인

기존 히트맵은 별도 주 화면에서 제거하고 `요인별 변화` 안의 접근 가능한 비교 표로 통합한다. 기존 이벤트 레이더는 상단 우선 카드와 일반 변화 목록으로 대체한다.

보조 탐색의 기본 화면은 현재 Radar 항목에서 직접 파생할 수 있는 `요인별 변화`다. 사용자가 선택한 탐색 화면은 해당 페이지에 머무는 동안만 유지하고, 새로운 영구 설정이나 저장 키를 추가하지 않는다.

각 보조 탐색은 독립적인 가용성·기준 시각·행 수를 유지한다. 한 데이터셋의 실패가 다른 탐색 화면을 숨기지 않는다.

## 상세 상호작용

### 기본 표시

우선 변화 카드, 일반 변화 행과 보조 탐색에서 `connectionKey`가 있는 선택 가능한 항목은 같은 선택 상태와 `MarketConnectionInspector`를 사용한다. Radar 신호와 연결할 수 없는 지도 표식과 집계 셀은 억지로 상세 진입점으로 만들지 않는다.

- 데스크톱은 공용 `DetailInspectorFrame`의 우측 드로어로 연다.
- 드로어 기본 너비는 520px이며 420–760px 범위에서 포인터와 키보드로 조절한다.
- Today·Stocks와 별도의 sessionStorage 키로 너비를 기억한다.
- `넓게 보기`로 중앙 모달 전환이 가능하다.
- 드로어와 모달 전환은 같은 상세 데이터를 사용하며 다시 요청하지 않는다.
- 밝은 오버레이를 사용하고 바깥 클릭은 상세만 닫는다.
- 바깥 클릭이 뒤의 카드나 행 선택을 변경하지 않는다.
- Escape로 닫고, 닫힌 뒤 최초로 상세를 연 항목에 포커스를 돌려준다.
- 모바일에서는 전환 버튼과 리사이저 없이 아래에서 올라오는 바텀시트를 사용한다.

### 상세 정보 순서

드로어와 모바일 바텀시트는 데이터가 있는 구역만 다음 순서로 보여준다.

1. 시장 변화 요약
2. 왜 지금 중요한가
3. 연결된 내 보유·관심 종목
4. 시장 변화가 종목까지 이어지는 영향 경로
5. 관련 뉴스·공시·근거 출처
6. 반대 근거와 확인할 리스크
7. 데이터 기준 시각과 근거 수준

원시 강도는 마지막 메타 구역에서만 노출한다. 값 옆에 `관측된 신호의 상대 강도이며 상승·하락 확률이나 가격 전망이 아닙니다`라는 의미 경계를 제공한다.

### 넓은 모달

넓은 모달은 같은 데이터를 2열로 재배치하고 다음 정보를 추가한다.

- 세계 지도 위치와 정밀도
- 전체 영향 경로
- 연관 기업과 테마
- 같은 유형의 이전 사건
- 요인별 비교 표

지도, 관계, 이전 사건과 비교 데이터가 없으면 해당 구역을 만들지 않는다. 부분 실패가 있으면 기본 변화 상세는 유지하고 실패한 구역에만 상태를 표시한다.

## 페이지 내부 모델

페이지 전용 모델은 실제 공개 계약을 변경하지 않고 `research-workspace` 페이지 모델 계층에 둔다.

```ts
type MarketConnectionStrength = 'high' | 'medium' | 'low';
type MarketConnectionScope = 'holding' | 'watchlist' | 'indirect' | 'market';

type MarketConnectionSummary = {
  changeCount: number;
  directConnectionCount: number | null;
  riskCount: number | null;
  analyzedAt: string | null;
};

type MarketConnectionItem = {
  connectionKey: string;
  priority?: 1 | 2 | 3;
  market: 'KR' | 'US' | 'GLOBAL';
  regionLabel?: string;
  title: string;
  summary: string;
  whyNow?: string;
  scope: MarketConnectionScope;
  strength: MarketConnectionStrength;
  rawStrength?: number;
  occurredAt: string;
  connectedEntities: Array<{
    entityKey: string;
    displayName: string;
    holding: boolean;
    watched: boolean;
  }>;
  primaryPath?: string;
  riskSummary?: string;
};

type MarketConnectionsModel = {
  summary: MarketConnectionSummary;
  priorityChanges: MarketConnectionItem[];
  marketChanges: MarketConnectionItem[];
};

type MarketConnectionDetail = {
  item: MarketConnectionItem;
  generatedAt: string;
  availability: 'available' | 'partial' | 'missing';
  evidenceLevel?: 'high' | 'medium' | 'low';
  paths: Array<{ id: string; label: string; summary?: string }>;
  sources: Array<{
    id: string;
    title: string;
    summary?: string;
    sourceName?: string;
    publishedAt?: string;
    url?: string;
  }>;
  risks: string[];
  counterEvidence: string[];
  checkpoints: string[];
  relatedEvents: MarketConnectionItem[];
  partialFailures: {
    relation?: string;
    impact?: string;
    geo?: string;
    history?: string;
  };
};
```

`rawStrength`는 서버 또는 fixture가 명시한 값을 전달할 때만 존재한다. 현재 Radar의 0–1 값은 `0.67 이상 = high`, `0.34 이상 = medium`, 그 미만은 `low`로 표시한다. 이 변환은 표시 라벨을 위한 고정 구간이며 우선순위 계산에 사용하지 않는다. UI가 라벨을 다시 숫자로 환산하거나 여러 값을 합산하지 않는다.

## 데이터 경계

### 개발 프리뷰

개발 프리뷰는 완전한 `MarketConnectionsModel`과 상세 로더를 제공한다.

- 동일한 시장 변화에 연결된 여러 종목 신호를 하나의 브리핑으로 통합한다.
- 우선 변화 3개와 시장 전반 목록을 명시된 fixture 순서로 제공한다.
- 모든 원문 링크는 유효한 HTTPS URL을 사용한다.
- 영향 경로, 리스크, 반대 근거, 체크포인트, 지도 위치와 이전 사건을 결정론적으로 제공한다.
- 실제 API 요청이나 인증 loader 없이 시나리오를 재현한다.

개발 프리뷰 검색 파라미터는 다음을 지원한다.

- `surface=market-connections`
- `scenario=default`
- `scenario=no-personalized`
- `scenario=empty`
- `scenario=partial`
- `scenario=detail-error`

### 실제 화면

현재 `RadarSignalPage`는 다음을 증명한다.

- `signalKey`, `entityKey`, 시장, 종목명과 티커
- 신호 유형, 극성, 0–1 강도와 요약
- 발생 시각과 출처 이름
- 보유·관심 여부
- 전체 건수, 다음 커서와 구성요소별 가용성·기준 시각·행 수

실제 화면 변환기는 이 정보만 사용한다.

- 각 Radar 항목은 하나의 시장 변화 항목이 된다.
- 여러 Radar 항목을 같은 사건으로 추정해 합치지 않는다.
- 보유·관심 플래그로 구역을 나누되 서버 순서를 보존한다.
- `connectionKey`는 `signalKey`, 제목은 종목명과 기존 신호 유형의 표시 라벨 조합, 본문은 기존 `summary`를 사용한다.
- 개인화 우선 카드는 불러온 서버 순서에서 `holding` 또는 `watched`인 첫 세 항목만 사용한다. 나머지 항목은 원래 순서를 유지한 일반 변화 목록으로 보낸다.
- `scopeTotal`은 전체 변화 수로 사용하지만 전체 직접 연결 수는 현재 응답으로 증명할 수 없으므로 `null`로 유지한다.
- `signalAsOf`를 분석 기준 시각으로 사용한다.
- 리스크 집계는 `null`로 유지한다.
- 원문 URL, 근거 수준과 상세 반대 근거를 생성하지 않는다.
- 종목 식별자가 있으면 기존 관계·영향 경로 API를 상세에서 부분적으로 재사용할 수 있다.
- 관계·영향 경로 실패는 기본 시장 변화 상세를 유지하고 해당 구역만 부분 실패로 기록한다.

향후 백엔드가 시장 변화 단위의 배치 read model을 제공하면 같은 페이지 모델을 서버 응답으로 채운다. 이번 구현에서 공개 Radar 계약을 미리 확장하지 않는다.

## 데이터 부족과 실패 처리

- 개인화 연결이 없으면 우선 카드 구역을 빈 카드로 채우지 않고 시장 전반 변화 목록을 첫 콘텐츠로 올린다.
- 전체 신호가 없으면 지도나 점수를 꾸며내지 않고 단일 빈 상태를 보여준다.
- 리스크 집계가 없으면 `—`와 `집계 데이터 없음`을 표시한다.
- 대표 영향 경로가 없으면 카드에서 해당 문장을 숨긴다.
- 원문 URL이 없으면 출처 이름만 표시하고 클릭 가능한 링크를 만들지 않는다.
- 상세 필수 데이터 로딩에 실패하면 선택 상태를 유지하고 상세 안에서 다시 불러오기를 제공한다.
- 관계·영향·지도·이전 사건 중 하나만 실패하면 다른 상세 구역은 유지한다.
- 오래된 구성요소는 값을 숨기지 않고 기준 시각과 `갱신 지연` 상태를 함께 표시한다.
- 추가 페이지 실패는 기존 목록을 유지하고 목록 하단에서 다시 시도할 수 있게 한다.

## 컴포넌트 경계

- `MarketConnectionsView`: 화면 순서, 선택 상태, 상세 열기와 페이지 추가 로딩을 소유한다.
- `MarketConnectionSummary`: 네 개의 상단 요약 값만 표시한다.
- `PriorityMarketChanges`: 우선 변화 최대 3개와 정직한 준비·빈 상태를 표시한다.
- `MarketChangeList`: 나머지 시장 변화, 연결 범위와 커서 페이지를 표시한다.
- `MarketExploration`: 세계 지도·요인별 변화·전파 경로·시간 흐름을 보조 탐색으로 제공한다. `connectionKey`가 없는 집계와 지도 표식은 조회 전용으로 유지한다.
- `MarketConnectionInspector`: 상세 정보 순서와 부분 실패 구역을 소유한다.
- `DetailInspectorFrame`: 드로어·모달·바텀시트, 오버레이, 리사이즈, 포커스와 모션을 공용으로 유지한다.
- 기존 `market-overview` 모델의 지도·요인·전파·타임라인 파생 로직은 재사용하되, 화면 모드 내비게이션 소유권은 `MarketExploration`으로 이동한다.

각 하위 컴포넌트는 페이지 모델만 소비한다. fixture, 실제 Radar 응답 변환과 API 호출을 표시 컴포넌트 안에 넣지 않는다.

## 반응형과 시각 규칙

- 데스크톱은 우선 변화 카드 최대 3개를 한 행에 배치한다.
- 1240px 이하에서는 우선 카드와 일반 변화 목록을 한 방향의 세로 흐름으로 전환한다.
- 모바일은 모든 콘텐츠를 한 열로 표시하고 상세는 바텀시트만 사용한다.
- 지도와 비교 표는 페이지 전체 가로 스크롤을 만들지 않는 명시적 내부 스크롤 영역을 가진다.
- 긴 시장 변화, 종목명, 영향 경로와 리스크 문장은 카드와 상세 안에서 줄바꿈한다.
- 상승·하락, 연결 범위, 강도와 데이터 상태를 색만으로 구분하지 않는다.
- 우선 카드와 일반 변화 행은 같은 전체 보더·배경·그림자 선택 상태를 사용한다.
- 모든 모션은 기존 CSS와 로컬 motion 경계를 사용하고 `prefers-reduced-motion`을 지원한다.

## 검증 기준

- 개인화된 시장 변화가 시장 전반 변화보다 먼저 표시된다.
- 우선 변화 카드는 최대 3개다.
- 개발 fixture에서 같은 시장 변화의 여러 종목 신호가 하나의 브리핑으로 통합된다.
- 실제 Radar 변환기는 여러 항목을 임의로 합치거나 브라우저 우선순위 점수를 만들지 않는다.
- 목록에 원시 강도 숫자, 매수·매도, 목표가와 가격 예측 문구가 없다.
- 우선 카드, 일반 변화 행과 `connectionKey`가 있는 보조 탐색 진입점이 같은 선택 상태와 상세를 사용한다.
- 상세는 정해진 일곱 구역 순서를 유지하고 데이터가 없는 선택 구역을 숨긴다.
- 드로어가 페이지 기하를 바꾸지 않고 오버레이 클릭은 뒤 항목을 활성화하지 않는다.
- 너비 조절, 세션 기억, 모달 전환, Escape와 포커스 복귀가 Today·Stocks 계약과 일치한다.
- 드로어와 모달 전환 중 상세 네트워크 요청이 추가되지 않는다.
- 원문 링크가 있을 때만 새 탭으로 열리는 유효한 HTTPS 링크를 제공한다.
- 세계 지도·요인별 변화·전파 경로·시간 흐름의 데이터 없음, 부분, 오래됨과 오류 상태가 구분된다.
- `default`, `no-personalized`, `empty`, `partial`, `detail-error` 시나리오가 정직한 상태를 보여준다.
- 데스크톱, 1240px 이하와 390px 모바일에서 내용 잘림과 불필요한 가로 스크롤이 없다.
- 라이트·다크 모드, 키보드, Axe 접근성 smoke와 reduced-motion을 통과한다.
- Today·Stocks의 상세 드로어·모달·바텀시트 회귀 검증을 통과한다.
- 포맷, lint, typecheck, 전체 테스트와 build를 통과한다.
- 코드 변경 후 `graphify update .`를 실행한다.
